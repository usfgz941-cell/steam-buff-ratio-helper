# BUFF 数据与成本匹配

## 1. CSV 是成本账本

脚本把 BUFF 导出的购买记录当作“历史成本账本”。典型字段包括：

- 游戏；
- 饰品；
- 时间；
- 交易状态；
- 己方 Steam；
- 实际成交价格。

脚本只使用交易成功记录作为有效购买成本。

## 2. 为什么必须保存历史买入价

对于已经买入并等待 7 天后出售的饰品，实际挂刀比例必须使用当时真实成本。

例如：

```text
7 天前买入：¥4.96
今天 BUFF 市价：¥4.77
```

这件库存的实际成本仍然是 `¥4.96`。当前 BUFF 市价只用于判断“如果今天重新买一件”的理论比例，不能修改已经发生的历史成本。

## 3. 再次导入

建议每次直接导出最近一年的完整购买记录，而不是手工整理增量。

脚本会：

1. 解析 CSV；
2. 生成稳定记录 ID；
3. 与本地已有数据合并；
4. 自动去重；
5. 保留已有的“已售”状态。

## 4. 名称匹配

脚本会对名称做归一化，包括常见磨损名称和中英文格式差异。

匹配优先使用：

- 饰品名称；
- 磨损等级；
- Steam 当前物品的可用名称字段。

如果出现多个候选，界面会显示下拉框供手动选择。

## 5. 为什么不把 BUFF assetid 当永久 ID

BUFF 导出的链接里可能包含 `assetid / classid / instanceid`。

其中 asset id 更像“当前库存中的资产实例编号”，物品经历交易后可能变化，因此不能作为跨平台、跨交易的永久主键。

所以第一版没有把 BUFF assetid → Steam 当前 assetid 当成唯一匹配依据。

## 6. 同名多件：FIFO

如果你先后买了多件完全同名饰品：

```text
第 1 件：¥4.20
第 2 件：¥4.35
第 3 件：¥4.10
```

而 Steam 当前库存只告诉脚本“这是同名饰品”，无法百分百恢复每一件和历史订单之间的实例对应关系。

默认规则：

```text
FIFO = 最早买入、尚未标记已售的成本先使用
```

优点：

- 简单；
- 可解释；
- 长期账本容易保持一致；
- 对普通无溢价挂刀品足够实用。

## 7. 手动覆盖

FIFO 不是强制绑定。

如果你知道当前这件实际上对应另一笔成本，可以在出售窗口的成本下拉框里手动切换。脚本会记录当前 Steam asset 与选择的历史成本之间的本地关联。

## 8. 标记已售

出售成功后，把使用过的历史成本记录标记为“已售”。

作用：

- 下一件同名饰品不会继续重复使用这笔成本；
- FIFO 会自动推进到下一笔未售记录；
- 历史记录仍保留，方便追溯。

## 9. 特殊饰品

普通同名挂刀品可以用 FIFO，但以下情况不应完全依赖名称 + FIFO：

- 特殊磨损；
- 高价贴纸；
- 稀有图案；
- 纪念品；
- 同名但存在明显溢价差异的物品。

这些情况应手动确认具体成本记录。

## 10. 隐私

BUFF CSV 可能包含：

- Steam ID；
- 购买时间；
- 具体购买记录；
- 个人交易习惯。

因此 CSV 只应保存在本地，不应提交到公开 GitHub 仓库。
