# 第二轮查漏补缺：账户、数据、市场深度与安全

第一轮审计集中在手续费、汇率、推荐算法和分发架构。本轮补充容易在真实长期使用中暴露的问题。

## 1. 多 Steam 账户隔离（P0）

BUFF CSV 包含“己方 Steam”字段。成本数据库必须按 SteamID 分区：

- 当前登录 SteamID 与记录中的 SteamID 一致才自动匹配；
- 不一致时显示明确警告，不能静默使用另一账户的成本；
- 汇率设置、已售状态和 FIFO 队列也应按账户隔离；
- 诊断导出可包含脱敏 SteamID，例如仅保留末 4 位。

这是比别名匹配更优先的问题：一旦串号，比例计算看似正常但成本归属完全错误。

## 2. CSV 记录唯一性与重复购买（P0）

稳定记录键应尽量包含：

```text
SteamID + 交易时间 + goods_id + assetid + 价格 + 状态
```

注意：

- 同一秒可能有多笔相同商品、相同价格的真实订单，不能仅按名称 + 时间去重；
- 只导入“交易成功”，退款 / 失败记录不能进入可用成本；
- 重新导入完整一年记录时，应保留既有“已售”和人工匹配状态；
- CSV 字段按不可信输入处理，名称渲染使用 `textContent`，不执行公式或 HTML。

## 3. 成本分配与物品身份（P1）

应在 UI 中明确区分：

- **精确物品匹配**：能够通过当前 Steam 描述信息和记录特征确认；
- **会计成本分配**：同名多件无法精确区分时按 FIFO / 手动选择分配。

BUFF 导出的旧 `assetid` 在交易后可能变化，所以不能把它当永久主键。`classid + instanceid` 更适合描述类别，也不足以区分同名不同磨损值 / 贴纸组合。

推荐显示匹配置信度：高 / 中 / 低。

## 4. 市场深度数据源（P1）

只抓前 20 条具体卖单不足以估计大队列。可研究 Steam 页面使用的：

- `itemordershistogram`：按价格聚合的买卖盘深度；
- listing `render`：具体挂牌列表；
- `pricehistory`：价格和成交量历史（登录后）。

推荐组合：

1. histogram 用于价格档与数量；
2. render 用于验证最低几档和异常单；
3. pricehistory 用于估计日成交量与趋势；
4. 全部显示抓取时间并缓存。

## 5. 同价位排队的不确定性（P1）

页面无法可靠知道自己在同价位的精确队列位置。等待时间应输出区间：

```text
最低估计：只计算更低价卖单
保守估计：更低价卖单 + 当前同价位全部卖单
```

不能把 `queueAhead / salesVelocity` 显示成精确分钟数。

## 6. 买单与立即成交（P1）

推荐算法应同时读取最高买单：

- 候选售价低于或等于当前可成交买单时，可能立即成交；
- 买卖价差反映当前流动性；
- 低流动商品不能只看卖盘最低价。

## 7. 数据新鲜度与熔断（P1）

- 盘口短缓存，例如 30–90 秒；
- 成交历史长缓存，例如 15–60 分钟；
- 429 / 403 / 5xx 后指数退避；
- 连续失败后暂停自动刷新，只保留手动按钮；
- 超过有效期的数据必须标“陈旧”，推荐降为低置信度。

## 8. 本地数据备份与迁移（P1）

浏览器本地存储可能因清理站点数据、换浏览器或扩展重装而丢失。需要：

- `schemaVersion`；
- 一键导出 JSON 备份；
- 一键恢复；
- 迁移前自动备份；
- 不把个人数据同步到公开 GitHub。

## 9. 汇率异常与断网（P1）

- NBU API 失败时使用最后一次成功值，并显示时间；
- 周末 / 节假日的最新有效交易日要明确；
- 手动汇率始终可用；
- 汇率变化幅度异常时不静默覆盖手动决策。

## 10. UI 兼容性（P1）

- 不依赖“买家支付 / 您收款”等中文文本定位；
- 优先稳定 ID、输入控件关系和 Steam 页面对象；
- MutationObserver 监听出售窗口创建 / 销毁；
- 避免重复注入面板和重复绑定事件；
- 支持 Steam 页面局部刷新而无需整页刷新。

## 11. 安全与发布（P0/P1）

- 正式版取消运行时远程 `eval`；
- 最小化 `@connect`；
- 安装文件、源码和 tag 对应；
- CI 扫描 SteamID、CSV 文件名、密钥、Cookie API 等敏感内容；
- 不实现自动勾协议、自动确认和手机确认绕过。

## 优先顺序

1. 多账户隔离；
2. 精确手续费 / UAH 取整；
3. 真实页面验收与诊断导出；
4. 数据唯一键、已售状态和备份；
5. histogram + pricehistory 的推荐算法 V2；
6. 单文件构建与正式 release；
7. 别名和高级物品匹配。
