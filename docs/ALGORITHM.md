# 比例与推荐挂价算法

## 1. 实际挂刀比例

脚本计算的是“这件已经买入的饰品，最终换成 Steam 钱包余额时的实际比例”。

```text
实际比例 = BUFF 实际买入成本（CNY × CNY→UAH 汇率） / Steam 实际到账 UAH
```

其中：

- BUFF 成本使用历史订单实际成交价，不使用当前 BUFF 市价；
- Steam 分母使用出售框里的 **“您收款”**；
- 汇率默认使用 NBU 官方 CNY→UAH，也可改为手动固定值。

### 为什么不用“买家支付”

“买家支付”包含 Steam 与游戏手续费，而用户真正得到的是“您收款”。此外 UAH 存在整数取整与最低手续费问题，直接读取 Steam 最终到账能避免重复模拟手续费。

## 2. 比例底线

默认底线为：

```text
0.70
```

含义：

- `0.64` 比 `0.70` 更好；
- `0.70` 是允许的最高比例；
- `0.71` 已超过底线。

脚本会反推出“为了不超过底线，买家支付至少需要多少”。反推过程优先调用 Steam 页面自身的手续费计算函数；不可用时才使用近似手续费并逐单位校正。

## 3. 市场数据

脚本读取：

- 当前前 N 个 Steam 卖盘，默认 N = 20；
- 每个价位的挂牌数量；
- 近 7 日成交价格；
- 近 24 小时成交量（可用时）。

卖盘会按相同价格聚合，例如：

```text
₴56 × 2 / ₴58 × 3 / ₴59 × 4
```

## 4. 价格步长

UAH 当前按整数格里夫纳处理，因此推荐价步长按 `₴1` 处理。

其他货币则从相邻挂牌价差中推断可用步长。

## 5. 快速模式

目标：优先成交。

```text
快速价 = max(当前最低卖价, 比例底线价)
```

如果当前市场最低价已经低于你的比例底线，脚本不会为了排第一而突破底线，而是停在底线价。

## 6. 均衡模式

目标：避免无意义地砸低，同时不要排太长队。

核心判断：

1. 找当前前几个价位中的“密集卖盘”；
2. 判断最低价是不是少量异常低价单；
3. 统计到密集卖盘为止有多少件排在前面；
4. 用近期日成交量估算可接受队列；
5. 决定压在密集价位前一档、跟随密集价位，或挂在密集价位后一档；
6. 若推荐价明显高于近 7 日成交中位价，则限制在中位价附近。

当前经验规则：

- 前方队列较浅 → 倾向挂在密集价位后一档，少让价；
- 前方队列较深 → 倾向直接跟随密集价位；
- 最低价和主要卖盘差距明显 → 可能忽略少量异常低价单。

示例：

```text
₴56 × 2 / ₴58 × 3
```

若成交量正常，均衡模式可能选择 `₴59`，因为 ₴56 只有少量卖单，而主要卖盘集中在 ₴58，排队数量仍较浅。

## 7. 耐心模式

目标：接受更长队列，换取更低实际比例。

算法会根据近 24 小时成交量给出更大的“允许排队预算”，在前若干价位中寻找可以接受的位置，并参考近 7 日成交中位价。

耐心价不会低于：

- 均衡价；
- 比例底线价。

## 8. 当前算法没有处理的因素

以下因素暂时不做自动估值：

- 特殊磨损溢价；
- 高价值贴纸 / 印花组合；
- 纪念品特殊属性；
- 稀有图案；
- 市场突然发生的大幅消息面波动；
- 同一市场中不同地区玩家的短期行为差异。

因此推荐价只适合普通挂刀决策，特殊饰品应人工判断。

## 9. 后续优化方向

推荐价后续应重点提升：

1. **成交速度估算**：用最近成交量与前方队列估计大致等待时间；
2. **盘口变化趋势**：连续采样最低价和卖盘深度，区分上涨、横盘、下跌；
3. **异常单识别**：不仅看单个低价，还看低价单出现和消失速度；
4. **价格跳档识别**：寻找“多让 ₴1 是否真的换来明显更快成交”；
5. **用户偏好**：急卖 / 正常 / 不急对应不同等待成本。

其中最关键的不是把推荐价算得更复杂，而是回答：

> 多让这一档价格，究竟能换来多少成交速度？

只有这个因果关系估计得更准，推荐挂价才真正有价值。
