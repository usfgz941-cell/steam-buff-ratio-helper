# 社区方案参考与取舍

本项目不直接照搬任何一个现有插件；这里记录“哪些机制值得借鉴、哪些口径不适合当前用户场景”。

## 网易 BUFF 价格比例（找挂刀）插件

参考：

- https://greasyfork.org/zh-CN/scripts/410137-%E7%BD%91%E6%98%93buff%E4%BB%B7%E6%A0%BC%E6%AF%94%E4%BE%8B-%E6%89%BE%E6%8C%82%E5%88%80-%E6%8F%92%E4%BB%B6
- https://greasyfork.org/zh-CN/scripts/410137-%E7%BD%91%E6%98%93buff%E4%BB%B7%E6%A0%BC%E6%AF%94%E4%BE%8B-%E6%89%BE%E6%8C%82%E5%88%80-%E6%8F%92%E4%BB%B6/discussions

### 值得借鉴

- 在 BUFF 列表中直接显示“当前买入 → 当前 Steam 税后到账”的理论比例；
- 批量筛选挂刀商品，适合购买前决策；
- 支持不同 Steam 钱包币种和汇率配置。

### 不适合直接套用的地方

该类插件通常用**当前 BUFF 卖价**作为分子，回答的是：

> 现在重新买一件，理论挂刀比例是多少？

本项目在 Steam 解锁后出售时，需要用**用户 7 天前真实成交成本**，回答的是：

> 我手里这一件按这个售价卖，实际现金成本 / 钱包到账是多少？

这两个比例都可以正确，但用途不同，不能混用。

社区讨论也反复出现低价商品、整数货币和手续费取整导致的税后金额偏差。因此本项目最终以 Steam 出售窗口真实“您收款”为准。

## Steam Economy Enhancer

参考：

- https://github.com/Nuklon/Steam-Economy-Enhancer

### 值得借鉴

- 使用 Steam 页面钱包元数据；
- 货币取整兼容；
- 请求队列、缓存、退避与限流保护；
- “忽略最低若干异常单”、价格偏移和历史窗口可配置；
- 持久缓存与会话缓存分离。

### 本项目不采用

- 不做自动确认出售；
- 不做无人值守批量上架；
- 不读取 Steam Cookie / API Key；
- 不把“快速出售”放在成本和底线校验之前。

## SERT / 汇率服务类项目

参考：

- https://github.com/somespecialone/sert

此类项目说明 Steam 内部币种换算和现实外汇估值应分层处理。对本项目而言，Steam 隐含汇率适合诊断市场显示，NBU 适合统一参考，用户实际渠道汇率才适合衡量真实现金成本。

## SteamTracking

参考：

- https://github.com/SteamTracking/SteamTracking

它用于跟踪 Steam 前端资源变化。对本项目最有价值的是：

- 监控 `economy_common.js / economy.js / economy_v2.js` 的结构变化；
- 在 Steam 改动出售窗口、钱包字段或手续费函数后，尽早发现兼容性风险；
- 不把 DOM 文本和样式类当作长期稳定 API。

## 取舍总结

| 能力 | 社区常见方案 | 本项目选择 |
| --- | --- | --- |
| 购买前理论比例 | 当前 BUFF 价 / 当前 Steam 税后价 | 保留为辅助概念，不替代历史实际成本 |
| 出售时实际比例 | 常缺少历史成本 | CSV 历史成交成本 + Steam 实际“您收款” |
| 手续费 | 固定比例近似或页面函数 | 页面真实值优先，Steam 钱包元数据预估 |
| 汇率 | 单一自动汇率 | 实际成本 / NBU 参考 / Steam 隐含三种模式 |
| 推荐价 | 最低价减一档或固定偏移 | 排队数量 / 成交速度 / 风险 / 底线约束 |
| 自动化 | 可自动上架 | 只填建议价，最终出售由用户确认 |
| 网络请求 | 高频并发 | 队列、缓存、退避、数据更新时间 |
